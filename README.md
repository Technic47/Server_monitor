# Server Monitor: монитор сервера на BigTreeTech TFT35 V2.0

Настольный монитор параметров сервера. Дисплей BigTreeTech TFT35 V2.0 (STM32F103 + экран 480x320 + тач) работает
самостоятельно, без принтера. Данные ему приносит ESP-01 (ESP8266): он по Wi-Fi опрашивает Prometheus и маленький
сервис `docker-status`, а результат отправляет дисплею по UART.

Показывает:

- температуры CPU, GPU0, GPU1, SSD и нагрузку (полоски в %) с иконками, плюс RAM;
- плашку Docker (работает/всего), по нажатию список всех контейнеров: состояние, время работы, коды выхода;
- тревоги (перегрев, упавший или unhealthy контейнер): звуковой сигнал, красная строка, нажатие гасит.

## Как это устроено

```
 Prometheus :9090 ──┐
                    ├── Wi-Fi ──> ESP-01 ── UART 115200 ──> TFT35 V2.0
 docker-status :8099┘   (опрос каждые 3 с / 10 с)          (STM32F103, ILI9488, тач)
```

Серверная часть ничего не знает про монитор: это обычные HTTP-источники. Поэтому монитор можно направить на любой
компьютер, где есть Prometheus с нужными метриками (см. раздел «Привязка к другому компьютеру»).

## Что нужно для работы

### Железо

| Что | Примечание |
|---|---|
| BigTreeTech TFT35 V2.0 | питание 5 В по разъёму Power (около 300 мА) |
| ESP-01 (ESP8266, 1 МБ flash) | устанавливается в разъём WIFI на плате дисплея |
| ST-Link V2 | прошивка дисплея по SWD (SWDIO, SWCLK, GND, RST; 3,3 В не подключать, дисплей питается отдельно) |
| USB-UART (CP2102) | нужен только для первой прошивки ESP-01; дальше ESP обновляется по Wi-Fi |
| Блок питания 5 В 1 А и выше | USB-зарядка или порт USB 2.0 (по току впритык) |

### Серверная часть (на компьютере, который мониторим)

| Что | Зачем | Обязательно |
|---|---|---|
| Prometheus, порт 9090 доступен по сети (не только внутри Docker) | источник температур и нагрузки | да |
| Экспортеры: `node_exporter` (Linux) или `windows_exporter` (Windows), плюс GPU-экспортер (например, nvidia_gpu_exporter), `smartctl_exporter` для SSD, датчики температуры CPU | метрики для 9 запросов | нужные |
| Сервис `docker-status`, порт 8099 | сводка по контейнерам | нет (пустой адрес отключает) |
| Открытые порты в брандмауэре (9090 и 8099 для локальной сети) | ESP должен достучаться | да |

ESP-01 и сервер должны быть в одной сети без изоляции клиентов. Точных имён метрик нет в коде, они зависят от
экспортёров: запросы настраиваются на веб-странице ESP (см. ниже).

### ПО на компьютере разработчика

- Arduino IDE с двумя ядрами: STM32 (STMicroelectronics, 3.0.0) и ESP8266.
- Библиотека `Adafruit GFX Library`.
- Для серверной части: Docker (Compose).

## Быстрый старт

### 1. Сервер

1. Запусти Prometheus и экспортеры. Убедись, что `http://<сервер>:9090/` открывается с другого компьютера.
2. Подбери 9 запросов (4 температуры, 5 нагрузок), см. «Запросы». Удобно поручить это Claude Code: промпт 2 в
   `claude_code_prompts.txt` находит реальные метрики и выдаёт готовые строки `КЛЮЧ=запрос`.
3. Подними `docker-status` (промпт 1): `docker compose up -d --build`, проверка: `http://<сервер>:8099/` вернёт текст
   вида `SUM total=14 ok=12 warn=0 bad=2` и строки по контейнерам.

### 2. Прошивка ESP-01

Первый раз по проводу через USB-UART (потом достаточно Wi-Fi, см. «Обновление ESP по сети»):

| ESP-01 | USB-UART |
|---|---|
| VCC, EN | 3V3 |
| GND | GND |
| TX | RXI |
| RX | TXO |
| GPIO0 | GND (только на время прошивки, потом убрать) |

Arduino IDE: плата `Generic ESP8266 Module`, `Flash Size: 1MB (FS:none OTA:~502KB)`, Flash Mode `DOUT`,
скорость 115200. В начале скетча при желании поменяй `DEF_SSID`, `DEF_PASS`, `DEF_HOST`, `DEF_DK_HOST`
(значения по умолчанию на первый запуск; потом всё меняется с дисплея или в браузере). Поменяй `WEB_PASS`
и `AP_PASS` на свои.

### 3. Прошивка дисплея

Плата в Arduino IDE: `Generic STM32F1 series`, Board part number `Generic F103VCTx`, Upload method
`STM32CubeProgrammer (SWD)`. В папку со скетчем положи `build_opt.h` с одной строкой
`-DSERIAL_RX_BUFFER_SIZE=256` (иначе приёмный буфер UART переполняется и строки склеиваются).
Подключи ST-Link к разъёму SWD дисплея (SWDIO, SWCLK, GND, RST) и нажми Upload. Если тач не откалиброван,
при первом запуске калибровка стартует сама.

### 4. Настройка на устройстве

На дисплее: Menu → ESP-01 → Wi-Fi (список сетей, ввод пароля), Server (адрес Prometheus `ip:порт`),
Menu → Docker → Server (адрес `docker-status`). Всё сохраняется в памяти ESP и переживает перезагрузку.

## Привязка к другому компьютеру

1. **Метрики.** Установи на новом компьютере Prometheus и нужные экспортеры (для Windows: `windows_exporter`,
   GPU-экспортер, при необходимости LibreHardwareMonitor-экспортёр для температур; для Linux: `node_exporter`,
   `smartctl_exporter`, GPU-экспортер). Открой порт Prometheus 9090 для локальной сети.
2. **Docker.** Запусти `docker-status` на новом хосте, открой порт 8099. Если Docker не нужен, оставь адрес пустым
   (на веб-странице ESP или `SETDK:` без аргумента), опрос отключится.
3. **Адрес на мониторе.** Menu → ESP-01 → Server и введи `ip:9090`; Menu → Docker → Server и введи `ip:8099`.
   Либо открой веб-страницу ESP (`http://esp-monitor.local`) и измени «Сервер Prometheus» и «Docker».
4. **Запросы.** Другой компьютер даёт другие имена метрик. На веб-странице ESP замени запросы под новый набор
   экспортеров (поле запроса пустое = датчик отключён). Для Windows примеры: CPU load
   `100 - avg(rate(windows_cpu_time_total{mode="idle"}[1m])) * 100`, RAM
   `100 - 100 * windows_os_physical_memory_free_bytes / windows_cs_physical_memory_bytes`.
   Каждый запрос должен вернуть ровно одно число; нагрузка обрезается до 0..100.
5. **Проверка.** Страница ESP показывает таблицу «Состояние датчиков»: код HTTP и значение по каждому ключу.
   Код 200 «нет данных» = метрики нет; 400 = ошибка синтаксиса; -1 = сервер недоступен.

### Запросы

Ключи фиксированы: температуры `CPU`, `GPU`, `SSD`, `P102` (с порогами тревоги), нагрузки `LCPU`, `LGPU`, `LSSD`,
`LP102`, `LRAM`. На дисплее строки идут в порядке CPU, RAM, GPU0, GPU1, SSD. GPU0 это `GPU`/`LGPU`, GPU1 это
`P102`/`LP102`. Названия ключей и подписи можно менять в коде, но тогда нужно править и ESP, и дисплей.
Длина запроса не больше 159 символов (длиннее страница молча не сохраняет).

## Веб-страница ESP

`http://esp-monitor.local` (или IP, виден в Menu → ESP-01). Логин `admin`, пароль `WEB_PASS` из скетча.
Здесь запросы PromQL, пороги, адреса серверов, смена Wi-Fi и состояние всех датчиков. Если Wi-Fi недоступен
60 секунд, ESP поднимает точку доступа `TFT-Monitor-Setup` (пароль `AP_PASS`) с той же страницей на
`http://192.168.4.1`.

## Обновление ESP по сети

- Из Arduino IDE: Tools → Port → сетевой порт `esp-monitor`, пароль OTA = `WEB_PASS`.
- Из браузера: Sketch → Export Compiled Binary, затем `http://esp-monitor.local/update` и загрузить `.bin`
  (не `.with_bootloader.bin`).

Настройки (адреса, Wi-Fi, запросы) при обновлении сохраняются.

## Протокол ESP ↔ дисплей

UART 115200, строки с `\n`.

ESP → дисплей:

| Строка | Смысл |
|---|---|
| `CPU:63.4`, `GPU:`, `SSD:`, `P102:` | температуры, °C |
| `LCPU:23.5`, `LGPU:`, `LSSD:`, `LP102:`, `LRAM:` | нагрузка, % |
| `ALERT:CPU_OVERHEAT:95.4`, `ALERT:DOWN bs-db` | тревога (повторяется в каждом цикле, пока условие есть) |
| `DK:total;ok;warn;bad` | счётчики Docker |
| `DKI:<код>\|<сек>\|<рестарты>\|<exit>\|<имя>` | один контейнер (до 24 штук) |
| `DKEND:n` | конец кадра Docker |
| `CFG:srv=ip:port;wifi=1;ip=x;rssi=-56;dk=ip:port;ssid=<имя>` | настройки ESP (ответ на `GETCFG`) |
| `NET:<rssi>;<enc>;<ssid>`, `NETEND:<n>` | список сетей (ответ на `SCAN`) |
| `ACK:...`, `ERR:PROM:<код>`, `ERR:DOCKER:<код>`, `ERR:QUERY:<ключи>`, `ERR:NOWIFI`, `ERR:WIFI` | подтверждения и ошибки |

Дисплей → ESP: `GETCFG`, `SCAN`, `STATUS`, `DKNOW`, `SETSRV:host[:port]`, `SETDK:host[:port]`
(пусто = выключить), `SETWIFI:<ssid>\t<пароль>`, `MODE:FAST|SLEEP`.

Коды состояния контейнеров: `O` работает, `S` стартует (health starting), `P` пауза, `U` unhealthy,
`R` перезапускается, `X` остановлен. Счётчики: ok = O; warn = S + P; bad = U + R + X.

## Если что-то не работает

| Симптом | Причина и решение |
|---|---|
| `NO DATA FROM ESP` | ESP не отвечает по UART: проверь питание ESP-01 и вывод EN, перезапусти ESP (Menu → ESP-01 → Reset) |
| `PROMETHEUS UNREACHABLE (-1)` | Prometheus недоступен: порт 9090 не опубликован наружу контейнера или закрыт брандмауэром |
| `NO DATA: ключи` | запрос корректен, но метрики нет (или запрос неверный); смотри таблицу на веб-странице |
| HTTP 400 в таблице | синтаксическая ошибка PromQL в запросе |
| Плашка Docker `--` | `docker-status` недоступен: проверь `http://<сервер>:8099/` и брандмауэр |
| Веб-страница ESP грузится минуту | антивирус (например, Kaspersky) вставляет скрипт в HTTP-страницы; открой в другом браузере |
| IDE не видит ESP по сети | ESP ещё не подключился (подожди 30 с), либо брандмауэр блокирует mDNS; используй загрузку `.bin` через браузер |
| Искажённые строки на дисплее | нет `build_opt.h` с `-DSERIAL_RX_BUFFER_SIZE=256` |

## Известные ограничения

- Подсветка экрана на этой плате не управляется программой (отдельного пина нет), поэтому «сон» только гасит
  картинку и по умолчанию отключён.
- Измерение батареи (`BAT_ENABLED`) по умолчанию выключено, монитор питается от USB 5 В.
- Имена метрик и запросы по умолчанию примерные, их нужно подгонять под свои экспортеры.
- Имена контейнеров на дисплее обрезаются до 18 символов, в списке показывается не больше 24 контейнеров.
